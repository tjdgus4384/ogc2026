## 목표의 실상 (조준 보정)

실제 제출 최솟값 기준: P6 +9.5% (우리 최선 draw에서 +2.6%), P3 +11.0%,
**P4 +40.9% / P5 +35.3%가 진짜 설계 격차다.** P4·P5는 saturation 0.80/0.84의
중간 혼잡 영역 — 순수 배정도(P3형) 순수 포화도(P6형) 아닌 지점에서 격차가 최대다.

## 아키텍처: 시간-전진 결합 구성 + 전역 되돌림 (Joint Rollout Search)

핵심 원리: **결정 변수는 (bay, entry)이고 기하는 검증이다** — 그러나 검증을
완화(F5)가 아니라 **실제 배치**로 한다. 시간을 앞으로 걸으며, 각 단계에서
(누가 들어가는가, 어느 베이에, 어디에)를 함께 정하되, 결정의 가치를
**미래 시뮬레이션(rollout)**으로 평가한다 — F1·F2를 커밋 압력이 아니라
평가 함수로 해결한다.

```
상태      = (부분 보드, 미배치 집합, 현재 날짜 t)
행동      = 날짜 t의 입장 집합 S와 그 공동 배치 (exact 코호트 CP — 검증된 부품)
평가      = 즉시 비용 + greedy-완주 rollout의 최종 목적값   ← F2 해결
분기      = 행동 후보 2~4개 (S의 크기/구성 변형)             ← 빔 폭
되돌림    = rollout이 현 최선보다 나쁘면 대안 행동           ← F1 해결
배정      = 행동 생성 시 Z3 비용을 목적값 그대로             ← F3 해결
좌표      = 코너 후보 + bottom-left 규율                     ← F7 완화
```

rollout 비용이 지배 변수다: greedy 완주 1회 ≈ 0.1~0.6초, 날짜 ~100개 ×
분기 3 × rollout 1 ≈ 30~180초 — TL 안에 들어온다. 이것이 기존 어휘로 표현
불가능했던 이유: 드라이버의 어떤 연산자도 "미래 시뮬레이션으로 현재 결정을
평가"하지 않는다 (모든 수리는 즉시 목적값만 본다).

## 재사용 지도

| 부품 | 출처 | 상태 |
|---|---|---|
| exact 코호트 배치 CP | cohort.py / exact_realizer.py | 증인 검증 통과 |
| 쌍충돌 모형 | builds/pc2 (api.cpp) | 결정적 0쌍 검증 |
| greedy rollout | insertGreedy (커널 그대로) | 출하 품질 |
| 바닥/게이트 | v6.3 | 출하 중 |
| 판정 규율 | abgate + 서로소 이중 게이트 + train | 확립 |

## 단계별 게이트 (각 단계는 하루 안에 판정 가능해야 한다)

```
S1  rollout 평가기 단독: 부분 보드 → greedy 완주 목적값. 결정적, 비용 측정.
    게이트: 완주 1회 < 1초 (P4/P5 크기).
S2  1-스텝 판정: 날짜 t 하나에서 행동 2~4개를 rollout으로 고르면, 항상-greedy
    행동보다 최종이 좋아지는가. 게이트: P4/P5 시드 수준에서 방향 있는 이득.
S3  전 구간 빔(폭 2~3): 구성 완주. 게이트: 씨앗 대비 우위 + Z3 부채 없음(F3 검사).
S4  bare 400초 고원 시험 (확립된 절차). 게이트: P4/P5에서 대조군 이하.
S5  드라이버 통합 아님 — 이 솔버가 드라이버를 대체하는 방향으로 (F4 회피):
    rollout 구성 + 어닐 마무리를 자체 TL 배분으로. 서로소 이중 게이트 + train.
```

S2가 이 설계의 사활 판정이다: rollout 평가가 1-스텝에서조차 이득을 못 내면
이 아키텍처도 기각하고, 그 기록이 명세에 추가된다.

## 08-13 갱신: 이 명세의 전제 중 무엇이 바뀌었나

### C1을 강화한다 (조건 제거)

C1("현 해는 표현 가능한 모든 이동의 고정점")은 그동안 **코너 어휘 위에서만** 성립하는
조건부 진술이었다. `mid1`이 그 조건을 시험했다 — 최후 경로에 인접 코너 좌표의 중점을
후보로 추가해도 4보드 × 3순서, 약 2,400회 삽입에서 **목적값과 Z1이 완전히 동일**하다.
비코너 위치는 아무것도 앉히지 못한다. **C1은 이제 무조건적이다.**

### 새 제약 C6: 예산으로는 닫히지 않는다

P6의 TL300 대 TL900이 3.6%다. 로그 외삽으로 P5의 26% 격차에는 약 3400배가 필요하다.
**커널 속도 최적화는 이 목표에 무가치하다** — 2배 빠르게 만들어야 ~2%이고, 오늘
검정력표상 2%는 P5에서 93쌍이 있어야 보인다.

### 새 제약 C7: 용량은 어떤 지각도 강요하지 않는다

`tools/z1bound.py`의 구간별 에너지 논증으로 **Z1 하한이 네 보드 모두 0**이다.
격차는 전부 기하(적재·크레인 접근)이며, 우리에게 없는 것은 **기하 하한**이다 —
그것을 구하려면 적재 자체를 풀어야 하므로 같은 난이도로 되돌아간다. 이것이 이 캠페인의
모든 진단이 자기참조였던 이유다.

### F4의 정정: 상한은 "출발점"이지 "변경"이 아니다

F4는 "출발점 상한 ~1%"로 기록됐고 `jointcon`이 정확히 그 벽에 부딪혔다. 그러나 v6.4는
-5%를 냈다. 차이는 **어디에 작용하는가**다:

```
출발점만 바꾼다        어닐이 씻어낸다 -> ~1%
매 삽입을 바꾼다       어닐 안에서도 유지된다 -> -5%
```

**따라서 rollout 아키텍처(S1~S5)의 재평가가 필요하다.** 그 설계는 구성 단계의 결정
품질을 높이는 것인데, (a) 구성만 바꾸면 F4의 상한에 걸리고, (b) rollout 평가는 결정당
비용을 크게 올려 "반복당 품질을 반복 수로 사면 6연패"에 정면으로 걸린다. S3가 기각된
것이 그 두 이유의 합이다.

### 성공한 형태 (v6.4)

```
1. 미리 계산/유지되는 신호로            (dayLoadE — 구성 시 1회 계산)
2. 매 삽입을 싸게 바꾸고                (eBot 조정, O(1))
3. 그 자리에 필터가 없어야 한다          (예약 가드가 죽어 있었다)
4. 이로운 체제에서만 켠다                (부하 1.6 미만, 실행 중 판정)
```

3번이 결정적이다. `bayld`가 같은 1·2·4를 갖추고도 무효였던 것은 그 축(베이 순서)에
`areaRoom`이 이미 작동하고 있었기 때문이다. **다음 후보를 고를 때 형태만 옮기지 말고
그 축에 이미 무엇이 작동하는지 먼저 확인할 것.**

### 남은 미탐색

결합 시간 결정 하나. 단, 위 3번 기준으로 그 축에는 이제 v6.4가 작동하므로 여지가
줄었다. 그리고 08-13 검정력표(1% 검출에 182쌍, P4 277 / P5 369)를 만족하지 못하는

**애초에 측정되지 않았다.**
