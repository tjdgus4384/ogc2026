# 전면 코드 감사 — 각 축의 현재 형태 vs 최선/일반형 (2026-08-04)

읽은 범위: `solver/myalgorithm.py` 전체, `src/{core,crane,geometry,occ,repair,alns,knobs}.hpp`,
`src/api.cpp`. 판정 근거는 `docs/UNDERSTANDING.md`·`results/`·`archive/tools-probes/`.

원칙: **임의의 하드코딩 분류기·확률·상수를 하나의 적응 기제로 통합**한다. 간결해지면서
동시에 히든 인스턴스 일반화가 좋아지는 방향만 채택한다.

## A. 삽입 (repair.hpp) — 배치 결정의 핵심

| # | 현재 형태 | 문제 | 최선/일반형 | 위험·검증 |
|---|---|---|---|---|
| A1 | `scanBayAt`: **first-fit** — (ori × ys × xs) 열거 순서에서 처음 통과한 자리를 채택 | 선택이 결정이 아니라 **열거 순서의 부산물**. 사전식 순서에 최적성 근거 없음 | 실행가능 후보를 **점수화 후 최선 채택**(낭비면적·접촉·미래-차단 위험의 가중합). BESTFIT은 접촉 점수만 썼고 그때 충돌 모형은 불완전했다 | 삽입당 비용 증가 → 후보 상한 K로 제한. 40-쌍 판정 |
| A2 | 면적 스크린이 **항상 orient-0의 면적**을 쓴다 (`repair.hpp:318`) | 실제 배치되는 방향이 더 **작을 때 거짓-거부** → 후보를 아예 못 봄 | 스크린에는 **전 방향 최소 면적**(허용적), 용량 회계에는 실제 방향 면적 | ~~스크린이 느슨해질 뿐 정확성 무해~~ → **기각**: 거짓-거부가 곧 가지치기였다(판정표) |
| A3 | 베이 순서 = 확률 0.70/0.92로 **선호-정렬 아니면 셔플** | 두 개의 마법 상수 + 이분법 | 하나의 **점수 기반 소프트맥스 순서**(후회 + 혼잡 + 적합), 온도 1개 | 궤적 전면 변경 → 다시드 40-쌍 |
| A4 | 방향 순서 = 50% 확률로 **컴팩트 정렬 아니면 셔플** | 동일 | A3와 **같은 소프트맥스 기제로 통합** | 동일 |
| A5 | 진입일 열거 = 3단계(릴리스 당일 / 퇴출 이벤트의 **국소** 스캔 / stride 6 성긴 스윕) | 구조가 임시적. 단 실측상 결손 0/53 (`archive/tools-probes/insertion_gap.py`) | **이벤트 구동 단일 열거**: {릴리스} ∪ {전 퇴출} ∪ {전 진입} ∩ [eBot,eTop], 각 이벤트에서 베이 전체 스캔, 예산 초과 시 stride 폴백 | 비용 증가가 유일 리스크. 완전성은 이미 충분하므로 **우선순위 낮음** |
| A6 | `reserve()` 일자-건너뛰기가 **전역 fillRatio** 한 값과 비교 | 베이별 실제 가용면적 차이를 무시 | 일자별 수요를 **베이별 도달가능 면적**과 비교 | 저위험, 중간 이득 추정 |

## C. 드라이버 (myalgorithm.py)

| # | 현재 형태 | 문제 | 최선/일반형 |
|---|---|---|---|
| C1 | `_spec_rule`: (m≤3 ∧ 포화<0.6) → prefp 0.85 | **인스턴스-특징 하드코딩 분류기** = 히든 일반화 위험(과거 selector가 LOIO 실패한 그 실패양식) | 짧은 **레이싱**으로 구성 선택(측정된 진행률 기준) |
| C2 | rounds = (sec≤110 ? 2 : 1) | 하드코딩 임계 | C1과 같은 레이싱에 흡수 |
| C3 | 인구-탐색 게이트 = (sec≥150 ∧ sec/n≤1.6) | 하드코딩 임계 | 동일 흡수 |
| C4 | 슬라이스 = TL의 **고정 30%**, K=25, 6% 슬라이스 | 암 선택은 적응(초당 수익), **크기는 고정** | K와 share도 같은 초당-수익 기제로 적응 |

**통합 제안(핵심)**: C1-C4의 네 개 하드코딩 게이트를 **하나의 시간-배분 밴딧**으로 대체한다.
이미 슬라이스 암이 "초당 수익으로 두 팔에 시간을 나눠주는" 형태로 존재하므로, 그 기제를
구성(prefp/rounds/pop/K/share)까지 확장하면 **코드는 줄고 일반화는 올라간다**.

## 다음 캠페인의 첫 빌드: 블록-쌍 3D 직교 패킹 모형

전역 배치 MIP(후보-변수 + 쌍-충돌 절단)는 어휘를 키우는 순간 무너진다 — 격자 어휘에서
CP-SAT 분리는 라운드당 700-1,100절단을 넣고도 14라운드 내내 `vp_bad≈199`, 모형 목적은
`obj=0`(전 블록 정시+최선호)에서 내려오지 않았다(잡 63184). 필요한 절단 수가 후보 수의
제곱으로 폭발하기 때문이고, 이건 인코딩의 문제지 솔버의 문제가 아니다.

**대안 인코딩(확정)**: 변수를 후보가 아니라 블록 자체로 잡는다.
- 블록 i마다 (베이 j_i, x_i, y_i, 방향 o_i, 진입 e_i). 점유는 3D 박스 (x, y, [e, e+P)).
- 제약은 **블록 쌍**마다 하나의 분리 논리합: 다른 베이 ∨ x-분리 ∨ y-분리 ∨ 시간-분리.
  n=150이면 쌍이 11k개 — 후보-쌍(수억)과 비교 불가능하게 작다. 논리합의 x/y 폭은 선택된
  방향의 bbox 치수에 조건부이므로 방향 수만큼 분기하지만 자릿수 이득은 유지된다.
- **단항 제약 2개 필수**(쌍-분리로 대체 불가): 베이 포함(선택 방향의 bbox가 베이 안에), 그리고
  릴리스 e_i ≥ R_i. 이 둘을 넣어야 "무조건 체커-실행가능"이 실제로 참이 된다.
- 부수 이득: 시간이 겹치는 쌍의 공간이 분리되므로 **동시-진입/동시-퇴출 타이브레이크 결함
  (BUILD.txt가 명시한 인증-불가 클래스)이 이 인코딩에서는 원천적으로 소멸한다**.
- **건전성**: bbox 분리 ⇒ 동일-레이어 폴리곤 분리 ⇒ 규칙 1 충족. 시간이 겹치는 쌍은 공간이
  분리되므로 크레인 규칙 2-5도 자동 충족(수직 스윕이 만날 상대가 없다). 즉 **이 모형의 해는
  무조건 체커-실행가능**하다.
- **한계(정직)**: 우리 보드는 맞물림(interlock)으로 bbox 이용률 103%를 쓰고 있어 현 인컴번트는
  이 모형의 표현 밖이다. 따라서 이 모형은 인컴번트를 재현하지 못하고, 단독으로는 더 나쁠 수
  있다. 값어치는 (a) 보장된-실행가능 다양성 생성기, (b) bbox-패킹만으로 도달 가능한 품질의
  기준선, (c) 맞물림이 실제로 얼마를 벌어주는지의 정량화.
