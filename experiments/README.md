## 근본 결함: 같은 날 이벤트 순서

체커는 Stage 2에서 `present_at_entry = {b : b.entry < entry < b.exit}`로 같은 날
진입을 **제외**하고, 순서는 Stage 5가 **나열된 하나의 순서**로만 검증한다. 커널의
rule 2/4는 **모든 순서**가 가능할 것을 요구했다(진입의 64~74%가 해당).
퇴출 쪽은 rule 3/5의 타이브레이크가 진입일뿐이라 **진입일·퇴출일이 모두 같은 쌍**이
서로의 present 집합에서 빠져 검사되지 않았다(출하 보드에 21~44쌍).

m7은 rule 2a=Stage 2, rule 2b=배치 차단 그래프의 비순환성(위상정렬)으로 대응하고,
커널이 검증한 순서를 `entry_ranks()`로 방출기에 넘긴다. 빠른 경로(“A가 배치 전원을
통과하면 마지막에 넣으면 된다” = 기존 규칙)로 오늘 통과하는 배치는 동일 비용.

## 왜 최솟값에 못 가는가 (구조 진단, 08-12)

**고원(plateau)이다.** 같은 엔진의 4시드가 구조적으로 전혀 다른 해를 낸다 — 지각 집합
교집합/합집합이 P4 24% / P5 28% / P6 52%, 베이 배정이 4시드 모두 같은 블록은 13~33%뿐.
그런데 목적값은 draw 산포(6~12%) 안에 모두 들어온다. 좁은 basin에 갇힌 것이 아니라,
**거의 같은 값을 주는 배치가 무수히 많고 20% 나은 배치가 희귀**한 것이다.
이것이 GLS 실패(밀 곳이 없다)와 구성 축 실패(어디서 출발해도 같은 고원)를 함께 설명한다.

시간 곡선: P3 5×TL −0.006%, P5 −0.2% (포화), P4 −12.2% (반응).
다만 1× 아래로 내려가는 쪽은 가파르다 — a1이 절반씩 두 번 돌려 졌다.

시간 배분 실측: 삽입 86% / 제거 4% / 목적함수 평가 **0.05%** / 실패 삽입 2.2%.

**커널이 이미 알고 있던 것**: `alns.hpp spatialCompact`의 주석이 같은 병리를 기록해 두었다
("35-42% of bay area is free but scattered ... peak polygon utilisation 58-65% vs bbox
103-105%"). 다만 그 조각모음은 라운드 종료 후 1회만 돌고(공식 TL은 rounds=1이라 마지막 1회)
탐색 중에는 전혀 쓰이지 않는다. d1이 그것을 reheat마다 들여놓았고 — x만 밀고 (e,f)는
불변이라 목적값이 변하지 않는, 고원에 정확히 맞는 연산인데도 — 전체는 중립이었다.
고원 위에서 이웃을 개선하는 것만으로는 부족하다는 뜻이다.

**c1의 실패가 x1의 근거다.** 하드코딩 임계값을 내 추측으로 바꾸는 것은 같은 실수이고,
어느 보드에 무엇이 맞는지는 실행 중에 재야 안다 — 히든 인스턴스에서는 특히.

**e1의 실패는 x1의 근거를 강화한다.** e1은 임계값을 *제거*해봤고 그것도 무효였다.
즉 `m>=4`는 맞지도 틀리지도 않았다 — **구조 조건만으로는 어느 쪽이 나은지 결정
불가능**하다는 것이 측정된 것이다. 86개 중 60개(70%)가 m∈{3,4}에 몰려 있고
결선 히든 8개 중 ~3개가 이 분기에 걸리는데, 우리가 가진 어떤 정적 규칙도
그 3개를 옳게 보낼 수 없다. 남은 길은 실행 중 측정뿐이다.

**x1의 사활 전제 (짓기 전에 결정적으로 확인할 것):** 레이스는 짧은 관측으로
최종 승자를 고를 수 있어야 성립한다. F4(씨앗 우위가 드라이버에서 역전)와
"반복당 품질을 반복 수로 사는 시도 6연패"가 둘 다 반대 방향의 증거다.

## bf1 — 구성 단계 한정 best-fit (08-13, 사전 등록)

**왜 이것인가.** 원장이 이미 추론해 두고 한 번도 짓지 않은 마지막 칸이다.

```
측정된 원인   파편화가 지각 일수의 78~83% (P4 83 / P5 78 / P6 72, tools/blocked.py)
축이 살아있음 pos1이 규칙을 뒤집자 P4 +2.97% — Z1 지배 보드에서 위치 규칙은 작동한다
              (P3는 -0.00%인데 Z1=0이라 위치가 목적에 닿지 않기 때문 — 축 사망이 아님)
사후로는 불가  compact2d 0/29·0/65·0/127, 넛지 성공 26~141회 — 보드는 이미 압축 고정점
6연패 회피     구성 한정. 어닐은 first-fit 유지 — 반복당 품질을 반복 수로 사면 6번 진다
과적합 없음    구조 조건이 아니라 배치 규칙. 전 인스턴스 공통
```

**설계.** `scanBayAt`의 후보 집합·수용 검사는 그대로 두고 **순서만** 바꾼다:
싼 `hitsSnap`으로 전 후보 필터 → **접촉 길이**(잔류 블록과 맞닿은 둘레 + 벽 접촉)
내림차순 정렬(동점은 기존 bottom-left) → 그 순서로 `vpConservative`, 첫 통과 채택.
vp 호출은 여전히 첫 수용에서 멈추므로 비용이 first-fit 수준으로 묶인다.
지표가 면적이 아니라 접촉인 이유: `sh1`(순수 면적 최소화)이 형상 적합성을 버려
10W/24L +2.67% p=0.024로 기각됐다.

`knobs::bestFit()`(`OGC_BESTFIT`, 기본 0 = 출하 동작)로 게이트하고,
`api.cpp`의 구성 진입점 두 곳(`insertCapped`, `reconstruct_ordered`)에서만 켠다.
`alns.hpp`의 어닐 수리 경로는 건드리지 않는다.

**사전 등록한 판정 순서.**

1. **결정적 선검사** (`tools/bfprobe.py`, 게이트 아님). `reconstruct_ordered`는
   순서의 순수 함수이므로 복권이 0이다. 전 구성 순서에서 목적값이 동일하면
   접촉 순위가 후보를 가르지 못한다는 뜻 = **no-op, 게이트하지 않고 종료.**
2. 변화가 있으면 P4/P5/P6 12시드씩 36쌍. **P3는 제외** — Z1=0이라 구조적 A/A다
   (pos1이 P3에서 -0.00%를 낸 것이 바로 이 이유).
3. 방향성이 나오면 **서로소 시드로 복제.** 오늘까지 이 단계에서 뒤집힌 후보:
   ord1(P5 −7.09%→+1.75%), slc1(P5 −1.09%→+0.61%), spec5(P5 −1.02% vs e1 +4.29%).
4. 복제를 통과하면 train_final 40쌍.
