Build note (for code review)
============================
sscore.cpython-312-x86_64-linux-gnu.so is compiled from src/ (8 files, C++17):

  g++ -O3 -std=c++17 -funroll-loops -fopenmp -march=x86-64-v3 -ffp-contract=off -flto -shared -fPIC \
      $(python3 -m pybind11 --includes) src/api.cpp \
      -o sscore$(python3-config --extension-suffix)

Built with g++ 11.4 / pybind11 3.0 against python 3.12. utils.py is the
competition-provided checker, unmodified.

Runtime dependencies
--------------------
myalgorithm.py needs only the Python standard library plus this extension.
It will ALSO use ortools (cp_model) if the interpreter has it -- the import
is guarded and a failure is silent, so the solver runs unchanged without it.
No license and no network are required: ortools' CP-SAT is used, not a
commercial solver. Verified against ortools 9.15.6755, the version present
on the grading image.

What the last revision changed (v6.0, 2026-08-12)
-------------------------------------------------
0. INTRA-DAY EVENT ORDER (src/core.hpp, src/api.cpp, myalgorithm.py).
   The checker excludes same-day entrants from its Stage-2 present set
   and validates their relative order in Stage 5, i.e. only ONE order
   has to work. The kernel's placement test instead required every
   intra-day order to be legal (rule 2 put the whole batch under the
   newcomer, rule 4 put the newcomer under each of them), and 64-74% of
   blocks enter in a same-day, same-bay batch of two or more, so the
   test was rejecting boards the rules allow on exactly the congested
   days where tardiness is made. Rule 2 is now split to match: 2a is
   Stage 2 (strictly earlier residents), 2b is Stage 5 (the batch's
   "must enter before" relation has to admit a topological order), and
   Engine::entryRanks() hands the verified order to the emitter so the
   solution lists an order the kernel actually checked. A fast path
   keeps every placement the old rule accepted at the old cost: if the
   newcomer clears the whole batch it can simply enter last.
   The same-day EXIT tie-break was completed at the same time -- it
   read entry day only, so a pair sharing BOTH days sat in neither
   present set and its sweep was never checked (the class the v5.3 note
   below records as uncertifiable). Without that completion the entry
   change alone fails the checker.
1. EJECTION-OP HABITAT (src/alns.hpp, src/repair.hpp). Ops 8 and 9 were
   gated on which objective term led the SUM, which switched the only
   preference-chasing operator off on every tardiness-dominated board
   even though its term was still 0.61-0.97M points there. They are now
   enabled wherever they have work (any regret / any tardiness); both
   already return an empty removal when they find none.
   Measured, matched AB/BA pairs at the official limits on one node per
   pair: preliminary P3-P6, 48 pairs, 31W/16L, median -2.09% (sign test
   p=0.040; P6 alone 11W/1L, -3.58%, p=0.006). Full 40-instance training
   set, 40 pairs, 33W/6L, median -3.25% (p<0.0001), no fallbacks.

What the previous revision changed (v5.3, 2026-08-04)
-----------------------------------------------------
0. PAIR-CONFLICT MODEL COMPLETED (src/api.cpp pairConflicts). The CP
   re-placement arm ranks candidate placements against a pairwise
   conflict model; that model checked only the crane ENTRY descent, so
   dense proposals were rejected afterwards by the official checker on
   the EXIT sweep and the whole solve was discarded. Added the mirror
   rule (whichever block leaves first must clear the stayer's layers
   j>=k, simultaneous exits resolved by the same LIFO exit order the
   solution emits) and both descent directions when two candidates
   share an entry day. Verified tight (feeding an incumbent board as
   its own candidate set yields zero conflicts on 3 boards) and sound
   AGAINST THE ENGINE'S OWN vp ORACLE (1,047 accepted pairs sampled,
   zero violations). Scope of that claim: pairs whose entry AND exit
   days are both identical are resolved by a tie-break that the model,
   the oracle and the emitted operation order do not all share, so the
   oracle cannot certify that class; the official checker gate plus the
   rescue ladder remain the authority that decides what ships.
1'. Assignment polish replaced by an exact-delta descent: the balance
   (Z2), preference (Z3) and mover-tardiness (Z1) deltas of a relocate
   or swap are closed-form, so candidates are ranked exactly and the
   engine is paid only for geometric verification.

Earlier revision (v5.1)
-----------------------
1. FULL SIMPLIFICATION PASS: every refuted experiment path was excised
   with its code (48% less code than the previous submission; kernel
   config surface = src/knobs.hpp, ~60 env knobs removed). Verified two
   ways: fixed-seed canary trajectories are byte-identical to the
   previous submission's binary, and an 80-pair two-seed paired sign
   test on the 40-instance final training set is neutral (median
   +0.34%, p=0.21). Same algorithm, smaller and fully auditable.

2. GATE RESCUE AUDITION (myalgorithm.py _arm_free): the checker gate's
   relocation rescue can legalize a board at a real objective cost
   (measured draw: 3.9x on one training instance while sibling thread
   candidates at ~1/4 the objective sat unused). When a rescue costs
   more than 2% -- or the gate fails outright -- the runner-up thread
   candidates are auditioned through the same gate and the CHECKER-
   measured cheapest feasible board ships. Dominance-improving: the
   rescued board remains the floor, auditions are deadline-guarded.

3. Population path: the final evolve burst now shrinks to the remaining
   wall instead of being dropped (was wasting up to burst-1 seconds of
   the time limit on population-class instances).
